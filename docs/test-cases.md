# Test Case Specification – inventory.js

Käesolev dokument esitab ISO/IEC/IEEE 29119-3 standardile vastavad testijuhtumid laomooduli `inventory.js` testimiseks. Iga testijuhtum kirjeldab täpsed eeltingimused, sisendandmed, oodatava tulemuse ja seose konkreetse testiga koodifailis `inventory.test.js`.

| ID | Requirement | Type | Priority | Precondition | Input | Expected result | Test name in code |
|---|---|---|---|---|---|---|---|
| **TC-01** | REQ-01 | functional | High | `stock = { 'A-1': 5 }` | `restock(stock, [{ sku: 'A-1', qty: 3 }])` | Tagastab objekti `{ 'A-1': 8 }` | `REQ-01 restock adds quantity to existing sku` |
| **TC-02** | REQ-01 | functional | Medium | `stock = { 'A-1': 5 }` | `restock(stock, [{ sku: 'B-2', qty: 4 }])` | Tagastab objekti `{ 'A-1': 5, 'B-2': 4 }` | `REQ-01 restock adds unknown sku to stock` |
| **TC-03** | REQ-02 | functional | High | `stock = { 'A-1': 5 }` | Kutsutakse `restock(stock, [{ sku: 'A-1', qty: 3 }])`, seejärel kontrollitakse `stock['A-1']` ja viiteid | `stock['A-1'] === 5` ja `result !== stock` (algne objekt on puutumata) | `REQ-02 restock returns a new object, original unchanged` |
| **TC-04** | REQ-03 | functional | High | `stock = { 'A-1': 5 }` | `restock(stock, [{ sku: 'A-1', qty: 0 }])`, `qty = -1`, `qty = 2.5` | Iga vigase koguse puhul visatakse Error teatega `'qty must be a positive whole number'` | `REQ-03 restock throws on qty 0`, `REQ-03 restock throws on negative qty`, `REQ-03 restock throws on non-integer qty` |
| **TC-05** | REQ-04 | functional | High | `stock = { 'A-1': 5, 'B-2': 10 }` | `pick(stock, 'A-1', 2)` | Tagastab uue objekti `{ 'A-1': 3, 'B-2': 10 }` | `REQ-04 pick reduces quantity on valid input` |
| **TC-06** | REQ-04 | functional | High | `stock = { 'A-1': 5 }` | Kutsutakse `pick(stock, 'A-1', 2)`, seejärel loetakse `stock['A-1']` | `stock['A-1'] === 5` ja tagastatud viide erineb algsest | `REQ-04 pick returns a new object, original unchanged` |
| **TC-07** | REQ-04 | functional | High | `stock = { 'A-1': 5 }` | 1) `pick(stock, 'C-3', 1)` (tundmatu)<br>2) `pick(stock, 'A-1', 6)` (üle laoseisu)<br>3) `pick(stock, 'A-1', 0)` | 1) Viskab Error `'unknown sku'`<br>2) Viskab Error `'not enough stock'`<br>3) Viskab Error `'not enough stock'` | `REQ-04 pick throws on unknown sku`, `REQ-04 pick throws when qty > available stock`, `REQ-04 pick throws on invalid qty (0, negative, non-integer)` |
| **TC-08** | REQ-05 | functional | Medium | Massiiv kirjetest, kus 'A-1' esineb 2 korda ja 'B-2' esineb 3 korda | `findDuplicateSkus(items)` | Tagastab massiivi `['A-1', 'B-2']`, kus iga dubleeritud SKU esineb täpselt üks kord | `REQ-05 findDuplicateSkus returns each duplicate sku once` |
| **TC-09** | REQ-06 | performance | High | Genereeritud massiiv 20 000 elemendiga (`SKU-0` .. `SKU-18999`), milles on 1000 duplikaati | `findDuplicateSkus(items)` ning mõõdetakse `performance.now()` kestust millisekundites | Kestus `ms < 100` (reaalne tulemus pärast $O(n)$ Set parandust ~4 ms) | `REQ-06 findDuplicateSkus handles 20 000 items under 100 ms` |
| **TC-10** | REQ-07 | security | High | Tühi laoseis `{}` | `restock({}, [{ sku, qty: 1 }])` ja `pick({}, sku, 1)` pahatahtlike sisenditega: `<script>alert(1)</script>`, pikkus 21 tähte, tühikud, SQL süste, erimärgid | Iga vigase või ohtliku SKU puhul visatakse Error `'invalid sku'` | `REQ-07 rejects sku %j (%s)` |
| **TC-11** | REQ-07 | security | Medium | Tühi laoseis `{}` | Korrektsed piirväärtused: pikkus 1 (`'A'`), pikkus 20 (`'A'.repeat(20)`), kriipsuga (`'A-1'`) | Operatsioonid õnnestuvad ilma veata ja tooted lisatakse laoseisu | `REQ-07 accepts valid boundary skus (1 to 20 chars, letters, digits, dash)` |
| **TC-12** | REQ-08 | reliability | High | `stock = { 'A-1': 5 }` | `restock(stock, [{ sku: 'A-1', qty: 1 }, { sku: 'B-2', qty: 0 }])` kus teine element on vigane | Viskatakse viga ning algne `stock['A-1']` jääb endiselt väärtuseks `5` (atomaarsus säilib) | `REQ-08 failed restock leaves original stock unchanged` |
